## 2. 转换脚本设计（`scripts/build_web.py`）

**职责**：`output/` → `docs/`（幂等，每次清空 `docs/` 内容目录、保留 `.vitepress/`）。

**步骤**：

1. **读篇章结构**：复用 `book/config/parts.yaml`（篇 `name`/章 `id`+`title`），得到篇→章映射 + slug（`foundations`/`technical`/`applications`）。
2. **建目录**：`docs/{foundations,technical,applications}/` + `docs/preface/` + `docs/appendix/`。
3. **逐章转换**（核心，规则见 [01-信息架构.md §2.2](./01-信息架构.md)）：
   - 注入 frontmatter（title / description / sidebar.order）。
   - 正则替换图片：`![alt](../figures/XX/YY.png){width=15cm}` → `<figure class="fig"><img src="/figures/XX/YY.png" alt="alt" loading="lazy"><figcaption>…</figcaption></figure>`；去 Pandoc 属性；相对路径转绝对。
   - 章首插入章扉页 `<figure class="chapter-divider"><img src="/dividers/chapter-XX.png" class="no-zoom"></figure>`。
   - 注入 `prev:` / `next:`（按篇章顺序）。
   - 输出 `docs/<part>/chapter-<n>.md`。
4. **卷首/附录**：转 `01-作者简介` `02-序` `03-导读` `04-目录` `08-附录` → 对应 `docs/preface/*.md`、`docs/appendix/index.md`。
5. **篇页**：生成 `docs/<part>/index.md`（`layout: part-cover`，挂 `PartCover` 组件 + `part-XX.png`）。
6. **资源**：拷贝 `output/figures/` → `docs/public/figures/`，`output/dividers/` → `docs/public/dividers/`，`output/cover.png` → `docs/public/`。
7. **生成 sidebar**：按篇章顺序输出 `.vitepress/sidebar.ts`。

**伪代码**（示意，非最终实现）：

```python
# scripts/build_web.py（骨架）
PARTS = {"基础篇": ("foundations", "part-01"), "技术篇": ("technical", "part-02"), "应用篇": ("applications", "part-03")}

for part_name, (slug, divider) in PARTS.items():
    write(f"docs/{slug}/index.md", render_part_cover(part_name, divider))   # 篇页
    for ch in chapters_of(part_name):                                       # 来自 parts.yaml
        md = read(f"output/{part_dir}/{ch.file}")
        md = inject_frontmatter(md, ch)
        md = re.sub(IMG_PANDOC, to_figure_html, md)                         # 图片转换
        md = insert_chapter_divider(md, ch.id) + md
        md = inject_prev_next(md, prev_ch, next_ch)
        write(f"docs/{slug}/chapter-{ch.id}.md", md)

copytree("output/figures", "docs/public/figures", dirs_exist_ok=True)
write(".vitepress/sidebar.ts", render_sidebar(PARTS))
```

> 备选落点：把这套逻辑加进 `src/book_builder/`（如 `web.py`），挂 `book-builder web` 命令，与 `build/pdf/sample` 并列。**推荐独立脚本起步**（不污染 book-builder、可独立迭代），稳定后再决定是否并入。

    "medium-zoom": "^1.1.0",

  }

> 与 online 对齐 VitePress `1.6.4` + Vue `3.5.40`；新增 `medium-zoom`。
> 不需要 echarts / datav-vue3（那是 online 仪表盘用的，书站用不到）。

## 5. GitHub Pages 部署（`.github/workflows/deploy.yml`）

直接复用 online 的 `deploy.yml`，仅改 artifact 路径（online 是 `.vitepress/dist`，book 因 `srcDir=docs` 产物在 `docs/.vitepress/dist`）：

```yaml
# 关键差异（相对 online/deploy.yml）
- run: pnpm install
- run: pnpm run build:web        # 先转换再构建
- uses: actions/upload-pages-artifact@v3
  with:
    path: docs/.vitepress/dist   # ← book 的构建产物路径
```

其余（pnpm setup、node 22、pages 权限、concurrency）与 online 一致。

## 6. 域名 book.dc3.site

1. **CNAME 文件**：`docs/public/CNAME`，内容一行 `book.dc3.site`（VitePress 会把 `public/` 原样拷进产物，GitHub Pages 据此识别自定义域）。
2. **DNS**（你在域名商处配）：添加 `CNAME` 记录 `book → <你的GitHub用户名>.github.io`（如 `pnoker.github.io`）。
3. **GitHub 仓库设置**：Settings → Pages → Custom domain 填 `book.dc3.site`，勾 Enforce HTTPS。
4. **base**：自定义域根路径，`base: '/'`（已在 config）。
5. **sitemap**：`hostname: https://book.dc3.site'`（已在 config）。

> online 的 `public/CNAME` 内容是 `dc3.site`；book 的 `CNAME` 是 `book.dc3.site` —— 两者独立子域，互不影响。

## 7. 风险与坑点（核验所得）

| 坑 | 说明 | 对策 |
|---|---|---|
| **Pandoc 图片属性** | `{width=15cm}` 不被 VitePress 识别 | 转换脚本正则去除（§2 步骤 3） |
| **图片相对路径** | `../figures/...` 迁到扁平 docs 后失效 | 转绝对 `/figures/...`（走 public） |
| **大图体积** | `output/*.pdf` 76MB，figures 累计也不小 | PDF 不打进站点 bundle，作下载链接；figures 用 `loading=lazy` |
| **章扉页被误放大** | `dividers/chapter-XX.png` 是装饰整图 | 加 `no-zoom` class，medium-zoom 排除 |
| **路由中文章符** | 文件名含 `：` `·` 在 URL/CI 上易出错 | 转换脚本统一输出英文 slug（`chapter-1`） |
| **CNAME 被覆盖** | 转换脚本若清空 `docs/public/` 会删 CNAME | 脚本只清内容目录，保留 `public/CNAME`、`logo.svg` 等手写资源 |
| **online 组件依赖** | `BookCover.vue` 等可能 import online 特有模块 | 迁移时核验 import，剔除 echarts/datav 相关依赖 |
