### 14.2.4 设备接入与数据流

设备接入不是把所有协议都转换成同一种网络连接，而是让不同 Driver 最终产生相同的位号值与命令语义。MQTT 设备可以主动发布，Modbus 设备通常由 Driver 轮询，OPC UA 可以订阅节点变化；协议入口不同，进入平台后的链路一致。

#### 从设备报文到位号值

以 MQTT 为例，设备报文可以使用 JSON，但 Topic 和字段结构由具体 Driver 定义，不存在全平台唯一的固定 Payload。Driver 完成连接、订阅、反序列化和设备/位号映射，再调用统一发送服务：

```json
{
  "deviceCode": "device-001",
  "timestamp": 1700000000123,
  "values": {
    "temperature": 25.6,
    "humidity": 68.2
  }
}
```

这段 JSON 只是协议设计示例，不应写成 IoT DC3 所有 MQTT Driver 的强制报文格式。

完整上行链路如下：

1. 设备通过 MQTT、Modbus、OPC UA 等协议与对应 Driver 通信。
2. Driver 按 Manager 元数据把原始数据转换为 `PointValue`。
3. `DriverSenderService` 将位号值发布到 RabbitMQ。
4. Data 的 `PointValueReceiver` 消费消息，按速率选择直接或批量保存。
5. Data 更新本地最新值缓存、写入 PostgreSQL Repository，再触发告警规则。
6. Web 或第三方应用经 Gateway 调用 Data API 查询最新值与历史数据；Grafana 可直接使用项目提供的 PostgreSQL 数据源配置。

下行命令走反向异步链路：客户端经 Gateway 调用 Data 的点位命令接口，Data 发布到 RabbitMQ，目标 Driver 消费并操作设备，执行结果再经 RabbitMQ 返回 Data。客户端应查询或订阅命令结果，而不是假定 HTTP 请求会一直阻塞到设备返回。
