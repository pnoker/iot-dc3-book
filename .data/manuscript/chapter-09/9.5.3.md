### 9.5.3 MCP协议工程原型：AI控制灯光

用户对智能音箱说“把客厅灯光调暗一些，再换一个暖色调”。传统实现通常将语音口令硬编码为设备API调用，语义稍有变化便无法理解。MCP协议的目标是让AI直接“读懂”设备语义，而非机械匹配模式串。

以下用简化工程原型展示MCP的核心交互流程。原型包含三个逻辑实体：AI Agent（语音助手）、MCP Broker、智能灯设备。所有消息结构、设备标识、参数数值均为示意，不指向任何真实产品或部署规范，目的是说明协议设计的工程思路。

**假设场景**：智能家居系统中，灯光设备通过MCP向Broker注册能力，AI Agent通过Broker发现设备，解析自然语言指令完成控制。

#### 设备注册与能力发现

设备启动后向Broker注册自身能力。注册消息的`action.capability`描述设备可读写属性和可执行动作。以下为示意注册消息（参数值均为假设）：

```json
{
  "header": {
    "msgId": "reg-001",
    "version": "1.0",
    "source": "device/light-living-01",
    "target": "broker/mcp-hub",
    "timestamp": "2025-03-21T10:00:00Z"
  },
  "context": { "tags": ["type:light", "room:living"] },
  "action": {
    "type": "register",
    "capability": {
      "deviceType": "light",
      "properties": [
        {"name": "power", "type": "boolean", "settable": true, "readable": true},
        {"name": "brightness", "type": "integer", "range": [0, 100], "unit": "%", "settable": true},
        {"name": "colorTemperature", "type": "integer", "range": [2700, 6500], "unit": "K", "settable": true}
      ],
      "actions": [
        {"name": "setBrightness", "params": ["brightness"]},
        {"name": "setTemperature", "params": ["colorTemperature"]}
      ]
    }
  }
}
```

Broker维护能力描述表。Agent初始化时查询Broker，获取所有设备的标准化能力清单。

#### AI解析自然语言为MCP意图

Agent处理流程（示意）：

1. **意图识别**：判断为“调节灯光属性”，匹配到`setBrightness`和`setTemperature`。
2. **参数提取**：从“调暗一些”映射为亮度目标值（假设值），从“暖色调”映射为色温目标值（假设值）。
3. **目标定位**：根据“客厅灯光”查到设备ID。

Agent构造MCP请求消息。`context`段携带意图原始描述和偏好设置，即使设备不理解“暖色调”，也能通过`preferences`获得期望色温基准。

```json
{
  "header": {
    "msgId": "cmd-002",
    "version": "1.0",
    "source": "agent/voice-assistant-main",
    "target": "device/light-living-01",
    "timestamp": "2025-03-21T10:01:00Z"
  },
  "context": {
    "session": "session-user-abc123",
    "commandSource": "voice",
    "userIntent": "调节灯光风格和亮度",
    "preferences": {"defaultColorMode": "warm"}
  },
  "action": {
    "type": "execute",
    "operations": [
      {"action": "setBrightness", "params": {"brightness": 60}},
      {"action": "setTemperature", "params": {"colorTemperature": 3000}}
    ]
  }
}
```

#### 执行动作与状态更新

Broker路由消息到设备。设备解析并逐条执行操作，返回执行报告（`executionReport`）。`context.stateSummary`提供简洁当前状态摘要。

```json
{
  "header": {
    "msgId": "rsp-003",
    "version": "1.0",
    "source": "device/light-living-01",
    "target": "agent/voice-assistant-main",
    "correlationId": "cmd-002",
    "timestamp": "2025-03-21T10:01:05Z"
  },
  "context": {
    "session": "session-user-abc123",
    "stateSummary": "brightness=60, colorTemperature=3000K, power=on"
  },
  "action": {
    "type": "executionReport",
    "status": "success",
    "currentState": {
      "power": true,
      "brightness": 60,
      "colorTemperature": 3000
    }
  }
}
```

设备同时发布状态变更通知（经Broker广播），供其他订阅组件同步。

#### 异常处理

若指令包含设备不支持的操作——例如“灯光渐变为紫色”，而设备只支持色温调节——设备在报告中返回错误，遵循“渐进式失败”原则：能做的继续执行，不支持的给出提示。

```json
"action": {
  "type": "executionReport",
  "status": "partial_failure",
  "errors": [
    {"operation": "setColor", "code": "UNSUPPORTED_PARAM", "message": "渐变操作不在能力范围内"}
  ],
  "successfulOperations": [{"action": "setBrightness", "params": {"brightness": 60}}]
}
```

Agent读到`partial_failure`，可根据会话ID回退到用户确认流程，解释不支持渐变并询问是否仅执行亮度调节。

以下用Python模拟核心交互逻辑（示意代码，不依赖真实网络库，参数均为假设值）：

```python
import json, uuid, time

class MCPBroker:
    def __init__(self):
        self.devices = {}
    def process_message(self, msg: dict) -> dict:
        action = msg.get("action", {})
        if action.get("type") == "register":
            self.devices[msg["header"]["source"]] = action.get("capability")
            return {"status": "registered"}
        return {"status": "forwarded"}

class MCPDevice:
    def __init__(self, device_id: str, broker: MCPBroker):
        self.device_id = device_id
        self.broker = broker
        self.state = {"power": False, "brightness": 0, "colorTemperature": 3000}
    def register(self):
        msg = {
            "header": {"msgId": str(uuid.uuid4()), "version": "1.0", "source": self.device_id, "target": "broker/mcp-hub"},
            "context": {},
            "action": {"type": "register", "capability": {
                "deviceType": "light",
                "properties": [{"name": "brightness", "type": "integer", "range": [0,100]}],
                "actions": [{"name": "setBrightness"}]}}
        self.broker.process_message(msg)
    def execute(self, msg: dict) -> dict:
        ops = msg.get("action", {}).get("operations", [])
        for op in ops:
            if op["action"] == "setBrightness":
                self.state["brightness"] = op["params"]["brightness"]
        msg["action"] = {"type": "executionReport", "status": "success", "currentState": self.state}
        msg["header"]["source"] = self.device_id
        return msg

broker = MCPBroker()
device = MCPDevice("device/light-living-01", broker)
device.register()
agent_msg = {
    "header": {"msgId": "cmd-002", "source": "agent/v1", "target": "device/light-living-01"},
    "context": {"session": "sess-1"},
    "action": {"type": "execute", "operations": [{"action": "setBrightness", "params": {"brightness": 60}}]}
}
print(json.dumps(device.execute(agent_msg), indent=2))
```

输出（假设场景）：

```json
{
  "header": {"msgId": "cmd-002", "source": "device/light-living-01", "target": "agent/v1"},
  "context": {"session": "sess-1"},
  "action": {"type": "executionReport", "status": "success", "currentState": {"power": false, "brightness": 60, "colorTemperature": 3000}}
}
```

该原型揭示了MCP的工程基础：能力标准化描述使Agent无需预先知道设备细节；上下文段为AI提供语义“锚点”；分层错误报告给回退策略提供依据。三要素共同填平AI与物联网设备之间的语义鸿沟。
