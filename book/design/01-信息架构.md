## 2. 转换层（出版稿 → Web 稿）

### 2.1 为什么需要

章节 md 有**三个不兼容 VitePress 的点**，直接放进 `docs/` 会出错或难看：

| # | 现状（出版稿） | 问题 | VitePress 期望 |
|---|---|---|---|
| ① | `![图1-1 ...](../figures/chapter-01/fig-01-01.png){width=15cm}` | Pandoc 属性 `{width=15cm}` 不被 markdown-it 识别，**原样泄漏到页面** | 纯 `![alt](src)`，宽度由 CSS 控制 |
| ② | 相对路径 `../figures/...`（章节在篇目录下一层） | 迁到扁平 `docs/` 后路径失效 | 绝对路径 `/figures/...`（走 `public/`） |
| ③ | 无 frontmatter，直接 `# 第1章 ...` | 缺 title/description（影响 SEO、标签页标题、sidebar 命中） | 顶部 `---\ntitle: ...\n---` |

### 2.2 转换规则（before → after）

**图片（最关键）**

```markdown
# before（output 出版稿）
![图1-1 三次浪潮演进时间线示意](../figures/chapter-01/fig-01-01.png){width=15cm}

# after（docs Web 稿）—— 去属性、转绝对路径、图题落为 <figcaption>
<figure class="fig">
  <img src="/figures/chapter-01/fig-01-01.png" alt="图1-1 三次浪潮演进时间线示意" loading="lazy">
  <figcaption>图 1-1　三次浪潮演进时间线示意</figcaption>
</figure>
```

> 用 `<figure>` 包裹是为了一致的图题样式（编号 + 说明），并让 medium-zoom 只绑定 `<img>`。
> 也可退化为纯 md `![图1-1 ...](/figures/chapter-01/fig-01-01.png)`，图题靠 alt + CSS `::after`——更轻，但样式可控性差。**推荐 `<figure>` 方案。**

**frontmatter 注入**（每章顶部）

```yaml
---
title: 第 1 章　物联网概述：从工业软件到 AI 智能体
titleTemplate: 第 1 章 · 从工业软件到 AI 智能体
description: 工业软件的演进与局限、三次网络革命、物联网定义与要素、AIoT 范式重构。
sidebar:
  order: 1   # 用于「基础篇」组内排序
---
```

**章首插入章扉页**（可选，推荐）

章标题之后、正文之前，插入章扉页图作为视觉分隔：

```markdown
# 第 1 章　物联网概述：从工业软件到 AI 智能体

<figure class="chapter-divider">
  <img src="/dividers/chapter-01.png" alt="第 1 章扉页" class="no-zoom">
</figure>

## 1.1 工业软件的演进与局限
...
```

> 章扉页加 `no-zoom` class，避免被 medium-zoom 误放大（它本身是装饰性整图）。

**篇页**（每个篇首页，如 `docs/foundations/` 的 index）

```markdown
---
title: 基础篇 · 从工业软件到物联网平台底座
layout: part-cover        # 自定义布局（见 02-视觉与交互.md）
---

<PartCover src="/dividers/part-01.png" title="基础篇" subtitle="从工业软件到物联网平台底座" />
```

### 2.3 转换脚本设计（详见 [03-构建与部署.md](./03-构建与部署.md)）

- **落点**：给 `book-builder` 加一个 `web` 子命令（与现有 `build` / `pdf` / `sample` 并列，复用 `book/config/parts.yaml` 的篇章结构），或独立脚本 `scripts/build-web.py`。
- **输入**：`output/`（分章 md + figures + dividers）。
- **输出**：`docs/`（扁平化的 Web 稿）+ `docs/public/figures/` + `docs/public/dividers/`。
- **幂等**：每次清空 `docs/` 内容目录后重生成（`docs/.vitepress/` 保留）。
- 与 book-builder「组装」哲学一致：**手稿是源，Web 稿是产物**，不手改 Web 稿。

## 4. 目录结构（左侧 sidebar + 右侧 outline）

### 4.1 左侧 sidebar（篇/章两级，手写配置）

```ts
// .vitepress/sidebar.ts —— 由转换脚本根据 parts.yaml 自动生成，也可手维护
export const sidebar = [
  { text: '卷首', items: [
    { text: '关于作者', link: '/preface/author' },
    { text: '序',       link: '/preface/foreword' },
    { text: '导读',     link: '/preface/guide' },
    { text: '目录',     link: '/preface/contents' },
  ]},
  { text: '基础篇 · 从工业软件到物联网平台底座', collapsed: false, items: [
    { text: '第 1 章　物联网概述',     link: '/foundations/chapter-1' },
    { text: '第 2 章　物联网体系架构', link: '/foundations/chapter-2' },
    { text: '第 3 章　感知层技术基础', link: '/foundations/chapter-3' },
    { text: '第 4 章　网络层通信技术', link: '/foundations/chapter-4' },
    { text: '第 5 章　平台层与数据处理', link: '/foundations/chapter-5' },
  ]},
  { text: '技术篇 · 云原生与 AI 智能体能力', collapsed: false, items: [ /* 第 6–9 章 */ ]},
  { text: '应用篇 · 多场景实践与可信协作', collapsed: false, items: [ /* 第 10–14 章 */ ]},
  { text: '附录', link: '/appendix/' },
]
```

- **便捷性**：篇可折叠（`collapsed`），当前篇默认展开、其它篇收起；当前章高亮（复用 online 的 `.VPSidebarItem.is-active` 胶囊高亮样式）。
- **层级清晰**：篇 = level-0（粗体），章 = level-1。

### 4.2 右侧 outline（节的子目录，自动）

VitePress 从页面 H2/H3 自动生成「本页目录」。书的 `## 1.1` / `### 1.1.1` 天然契合：

```ts
themeConfig: {
  outline: { level: [2, 3], label: '本页目录' },  // 显示节 + 小节
}
```

> 不需要任何额外工作——这是采用 VitePress 的直接红利：**章是左侧目录，节是右侧子目录**，完全对应用户「便捷的目录和章节子目录」诉求。

### 4.3 上下章导航

每章页底自动出现「← 第 N-1 章　|　第 N+1 章 →」。两种实现：

- **A（推荐）**：转换脚本根据篇章顺序，在每章 frontmatter 注入 `prev:` / `next:`（VitePress 原生支持，标题自动取）。
- **B**：靠 sidebar 顺序隐式推导（VitePress 也支持，但跨篇边界控制弱）。

## 5. 搜索（全文 local search）

```ts
themeConfig: {
  search: { provider: 'local', options: {
    translations: { button: { buttonText: '搜索全书', buttonAriaLabel: '搜索' } },
  }},
}
```

- **构建时索引**全部章节正文 + 图题 + 表格，零外部依赖、零延迟、零申请。
- 中文分词由 MiniSearch 内置处理，对本书技术术语（物模型、SCADA、OPC UA、MCP…）覆盖足够。
- 若后期发现召回不佳，再切 Algolia DocSearch（需申请，非必需）。
