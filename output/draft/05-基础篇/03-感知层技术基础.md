# 第3章 感知层技术基础

## 3.1 感知层概述

感知层是物联网的"神经末梢"，把物理世界的状态转换成数字信号，是整个架构的数据源头。它的逻辑边界止于网络层入口——感知层负责"采"，不负责"传"。理解感知层，先抓住它提供的四项基础能力：**数据采集**（温度、压力、振动等物理量转数字信号）、**身份识别**（RFID 等回答"是谁"）、**位置感知**（GNSS/UWB 等回答"在哪"）、**初步处理**（边缘节点上的滤波、聚合、简单判断）。这四项能力贯穿全书后续——采集的数据进网络层、平台层，识别与定位为业务提供上下文，初步处理则是第 2 章讲的"边缘挡第一波"的起点。

感知层正在经历一次演进：从"只采不判"（传感器纯粹上报原始值，判断全靠云端）走向"边感边判"（边缘节点具备一定算力，能就地做滤波、聚合甚至轻量推理）。推动这次演进的是两股力量——算力下沉（边缘 AI 芯片成本下降）与带宽压力（海量设备原始数据全上云不现实）。这使得感知层不再只是数据管道的入口，而开始承担一部分决策职责，为第 7 章 AI Agent 在边缘侧的落地埋下基础。

## 3.2 传感器技术

传感器按被测物理量分类：温度（热电偶、热敏电阻、数字温度芯片）、压力（压阻、电容式）、振动（压电、MEMS）、光照（光敏二极管、CCD/CMOS）、气体（电化学、半导体）等。原理各异，但工程上更关心四项关键性能指标：**灵敏度**（输出变化与输入变化的比值）、**分辨率**（能分辨的最小变化量）、**线性度**（输出与输入的线性偏离程度）、**响应时间**（跟随输入变化的快慢）。这四项是选型与对比的通用语言。

**选型四维度**是感知层工程决策的核心：**精度**（测量是否够准，匹配业务需求即可，不必过度追求）、**成本**（单点成本乘以部署规模可能惊人）、**功耗**（电池供电设备的续航命脉）、**环境适应性**（温湿度范围、防护等级、抗干扰能力）。四个维度相互制约——高精度往往高成本高功耗，工业级环境适应性强但价格数倍于消费级。选型本质是在约束条件下找平衡，没有万能传感器，只有最匹配场景的传感器。一个实用方法：先画需求矩阵（场景的温度范围、所需精度、供电方式、预算），再据此筛选，而不是先看某款传感器参数再倒推场景。

传感器接口分两类。**模拟接口**传感器输出连续电压/电流信号，需要外部信号调理电路（放大、滤波、模数转换），工程师要对信号链的每一步负责——优势是灵活、可针对弱信号深度优化，劣势是设计复杂、易受干扰。**数字接口**传感器（I²C、SPI、UART）厂商已把调理封装在芯片内，直接输出数字值，开发简单、抗干扰好，是当今主流选择。两者权衡：弱信号或定制化场景选模拟，快速开发与可靠性优先选数字。

## 3.3 RFID 技术

RFID（Radio Frequency Identification，射频识别）解决物联网里"是谁"的问题——给物品一个可被无线读取的数字身份，无需光学对准或接触。它由三大核心部件组成：**标签**（贴在物品上，存储唯一标识如 EPC 码）、**读写器**（发射射频信号激活标签并接收回传数据）、**天线**（耦合读写器与标签的射频场）。标签按供电方式分三类：被动式（无电池，靠读写器场区供电，成本低体积小，读取距离近）、半主动（带电池只为芯片供电，通信靠读写器场区）、主动式（自带电池主动发射，距离远但成本高体积大）。

RFID 工作频率决定场景。低频 LF（125kHz，动物耳标、门禁）、高频 HF（13.56MHz，公交卡、NFC）、超高频 UHF（860–960MHz，物流仓储托盘追踪，是规模读取的主力）、微波 MW（2.45GHz，铁路车号）。大规模场景（一个读写器同时读上百标签）会遇"碰撞"问题，靠防碰撞算法（如帧时隙 ALOHA）解决。RFID 最成熟的应用是物流仓储与资产管理——给货箱托盘贴 UHF 标签，通过式读取即可批量盘点，显著减少人工扫描成本。

## 3.4 定位技术

定位回答"在哪"。室外室内用不同技术，关键看精度、覆盖、成本三者的平衡。

**室外定位以 GNSS（全球导航卫星系统）为主**。GPS 是大家熟悉的，中国的北斗三号（BDS-3）已于 2020 年全球组网运营，民用精度显著提升，手机级 RTK（实时动态差分）服务也在普及。按精度分三级：单点定位（米级，普通手机）、差分 DGNSS（亚米级）、RTK（厘米级，测绘、农机自动驾驶）。室外定位的局限是室内和无遮挡遮挡场景失效。

**室内定位**因为没有卫星信号，靠短距无线测距，三技术各有定位：Wi-Fi（利用已有路由，覆盖广但精度低，10–15 米）、BLE（低功耗蓝牙，5.4 版本的方向发现 Direction Finding 功能让测向更成熟，米级）、UWB（超宽带，厘米级，已集成进主流手机如 Apple U2，消费级生态成熟，成本仍较高）。

定位的物理基础是三种测距方式：**RSSI**（接收信号强度，距离越远越弱）、**ToA**（到达时间，电磁波飞行时间换算距离）、**AoA**（到达角度，天线阵列测向）。基于测距值，有两种定位思路：**三角测量**（已知几个基站的坐标和到目标的距离，解几何方程算位置）适合有明确基站布局的场景；**指纹法**（离线建位置-信号特征库，在线匹配）适合环境复杂、模型难建的场景，但需要离线建库。

## 3.5 边缘计算节点

边缘计算节点是算力下沉到数据源头的载体，承担"就近处理"职责。按硬件算力分三梯队：**MCU 级**（如 STM32，毫瓦级功耗，跑轻量控制与简单规则）、**应用处理器级**（如树莓派 5 代，瓦级功耗，跑 Linux 与中等算力任务）、**AI 加速级**（如 NVIDIA Jetson Orin Nano/NX、华为 Atlas，十瓦级功耗，跑实时模型推理）。2026 年的趋势是 NPU 集成进 MCU（如 STM32N6 带神经网络加速器）和国产边缘 AI 芯片（如瑞芯微 RK3588 NPU）普及，让端侧推理成本进一步下降。

边缘节点的部署位置分两类：**传感器侧**（紧贴设备，处理单点数据，如一个网关带几台设备）与**网关侧**（汇聚一片区域数据，做跨设备处理）。它承担三项预处理任务：**滤波去噪**（平滑原始信号、剔除明显错误）、**数据聚合**（按时窗降采样，减少上云数据量）、**异常判定**（基于规则或轻量模型本地判断，命中才上报，降低云端负载）。这三项是边缘"挡第一波"的具体内容——只把必要的数据和已判定的异常上传，而非原始数据全量上云。

## 3.6 端侧 AI 与自适应采样

端侧 AI 指在设备本地（MCU 或边缘芯片）跑机器学习推理，不必把数据送到云端。它的核心价值三个：**省带宽**（本地推理只上传结论，不传原始数据）、**低延迟**（无网络往返，毫秒级响应）、**保隐私**（敏感数据不出本地）。端侧 AI 的传统形态是 TinyML——在毫瓦级 MCU 上跑量化与剪枝后的传统 ML 模型（如关键词识别、振动分类）。2026 年，端侧能力正从传统分类/检测模型向轻量 SLM（小语言模型）推理延伸，Phi/Gemma/Qwen 等经量化的小模型已能在边缘设备本地运行，为更复杂的端侧理解打开空间。工具链上，Google 的 TFLM 已更名为 LiteRT for Microcontrollers，Edge Impulse 等端到端低代码平台成为主流部署路径。

模型轻量化的两个基础手段：**量化**（把权重从 float32 降到 int8，牺牲少量精度换大幅压缩）、**剪枝**（剔除冗余参数）。两者常组合使用，让模型塞进 MCU 有限的 Flash/SRAM。

自适应采样是与端侧 AI 配套的降功耗手段。固定频率采样（每秒采一次）对电池设备是负担，自适应采样按需调整：**事件驱动**（有事件才采，如门窗传感器平时休眠、触发才上报）、**变化率驱动**（变化大才高频采，平稳则低频）、**预测模型驱动**（用模型预测何时会有变化，提前加密采样）。三者结合，能大幅降低功耗与带宽，对电池供电的广域物联网设备尤为关键。

## 3.7 物模型与设备抽象

一台温度传感器上报的是数字 `28.5`，一台 Modbus 设备上报的是寄存器 `40001` 的值，一台摄像头上报的是 RTSP 视频流——异构协议、异构数据格式，上层应用若要直接对接，会被设备差异淹没。**物模型（Thing Model，或称 Profile）** 就是解决这个问题的抽象层：它给每类设备定义一张"能力卡片"，描述这台设备**能采什么（属性）、能控什么（服务）、会报什么（事件）**，屏蔽底层协议差异，让上层用统一的语义操作设备。

物模型由三要素构成：
- **属性（Property）**：设备的状态量，可读可写。如温度传感器的 `temperature`（只读）、空调的 `targetTemp`（可读写）。
- **服务（Service/Action）**：设备可被执行的操作。如空调的 `turnOn`、阀门 `open`，带输入参数与返回值。
- **事件（Event）**：设备主动上报的异步通知。如温度超限告警、故障码上报。

一个精简的温度传感器物模型示例：

```json
{
  "type": "temperatureSensor",
  "properties": {
    "temperature": { "type": "number", "unit": "℃", "readOnly": true },
    "humidity": { "type": "number", "unit": "%", "readOnly": true },
    "battery": { "type": "number", "unit": "%", "readOnly": true }
  },
  "services": {
    "calibrate": { "input": { "offset": "number" } }
  },
  "events": {
    "highTempAlarm": { "data": { "threshold": "number", "current": "number" } }
  }
}
```

物模型的核心价值是**平台无关**：上层应用或 AI 不再关心设备是 Modbus 还是 MQTT、是 A 厂还是 B 厂，只面向"属性/服务/事件"这套统一接口编程。这与 W3C WoT TD、oneM2M 等国际标准，以及智能家居领域 2022 年发布、2026 年已成为 Apple/Google/Amazon 共同遵守的事实标准 Matter，思路一致——都在用统一的设备能力描述打通异构生态。

异步场景下还有**设备影子（Device Shadow）**机制：设备离线时，平台维护一份"期望状态"与"实际状态"的影子，指令先写期望状态，设备上线后同步——这解耦了指令下发与设备在线状态，为第 7 章的异步指令执行埋下基础。

**物模型与 AI Agent 的衔接**是最关键的一点。物模型定义的属性读取、服务调用、事件订阅三类接口，天然映射为 AI Agent 的工具调用（Tool/Function Call）——Agent 要查温度就调属性读、要开阀门就调服务、收到告警就订阅事件。第 7 章将展示，IoT DC3 的 Agentic Center 正是把物模型接口封装成 `@Tool`，让 LLM 通过自然语言自主感知和控制物理设备。物模型因此成为连接"物理设备"与"AI 智能"的接口契约。

## 3.8 本章收束

感知层完成了从物理世界到数字世界的第一步转换。主线一句话：**物理感知（传感器）→ 身份识别（RFID）→ 空间定位（GNSS/UWB）→ 边缘处理（边缘节点）→ 局部智能（端侧 AI）→ 统一抽象（物模型）**。前五项是感知层自身的能力建设，最后一项物模型是感知层与上层（平台层、智能层）的交接点。

几个关键判断带走：传感器选型按精度/成本/功耗/环境四维度平衡，没有万能传感器；RFID 看频段选场景，UHF 是规模读取主力；定位看精度选技术，室外 GNSS、室内按精度选 UWB/BLE/Wi-Fi；边缘节点三梯队硬件对应三档算力需求，预处理三任务（滤波/聚合/判定）是"挡第一波"的具体内容；端侧 AI 用量化+剪枝塞进 MCU，自适应采样降功耗降带宽。最重要的是物模型——它把异构设备收敛成统一的属性/服务/事件接口，是后续平台层数据治理、智能层 AI Agent 调用设备的基础，第 5 章和第 7 章都会在这套抽象上展开。
