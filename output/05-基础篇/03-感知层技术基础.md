# 第3章 感知层技术基础

### 3.1.1 感知层的定位与核心能力

物联网项目从图纸走向落地，最先卡住的环节往往不是选云平台还是数据库，而是最底层的问题：机器怎么“碰”到物理世界。风机平稳还是抖动，集装箱在港口还是高速公路，电机过载还是正常——这些信息如果系统无法获取，后续所有监控告警、预测维护、闭环控制都是空谈。负责这第一步的技术层，就是感知层（Perception Layer）。

感知层处于物联网参考架构的最底层，直接面对物理世界。其核心职责是提供对物理世界的数字化映射【S12】。感知层包含各种传感器节点、RFID标签和读写器、定位模块等物理设备，这些设备通过嵌入式技术与外部环境交互，将物理量的变化转换为数字系统可处理的电信号与数值【S1】。

感知层需要落地的四项基础能力构成了物联网系统信任链条的起点：

- **数据采集**：利用传感器将物理量（温度、压力、振动、气体浓度等）转换为可处理的电信号。传感器的选型直接决定数据质量：量程是否覆盖目标范围、精度是否满足阈值告警要求、响应时间能否跟上动态变化——任何一个维度选错，都可能导致上层应用基于错误数据做出错误决策。物联网信号的处理通常经历“采集 → 分析/建模 → 决策 → 执行”的闭环，感知层的采集质量决定了后续环节的可用性【S2】。

- **身份识别**：通过RFID、二维码、NFC等技术，回答“这是什么东西”或“是哪个个体”。自动识别技术将物理世界与信息世界统一在一起，能够自主提取与被识别物体有关的数据信息并供上层处理【S6】。

- **位置感知**：借助GNSS（含GPS、北斗等）、基站定位、UWB、BLE信标等技术，提供被监测对象的空间坐标。不同技术的精度差异需要工程师根据场景做判断：仓储内AGV的精准停靠需要高精度定位，而运输车辆的大致路径监控则可接受较大误差【S6】。

- **初步处理**：在信号源头执行信号调理（放大、滤波）、模数转换（ADC）、数据格式化，甚至简单的逻辑判断。这是感知层从“被动采集”向“主动处理”迈进的第一步，显著降低了网络带宽与云端计算压力。

感知层的逻辑边界需要严格区分。如果感知层是一个传感网，则传感网中的感知节点、路由节点、汇聚节点及传感网所使用的网络（通常为短距离射频）都属于感知层。但汇聚节点向上层通信的功能属于网络层，因此一般将感知层的汇聚节点称为感知层网关节点【S8】。工程中常遇到物理设备“跨界”的情况——一个智能网关可能同时承担感知层（连接传感器）与网络层（蜂窝上行）双重角色，架构设计时必须将各层在逻辑上明确区分。例如，网关上的传感器接口电路属于感知层，而网关内部的4G模块及其协议栈属于网络层；调整传感器时不应影响网络通信配置，反之亦然。

### 3.1.2 感知层技术演进：从简单采集到智能感知

工程师排查冷库风机异常振动时，常遇到这样的困局：传感器以固定频率上报加速度值，当振幅突破预设阈值时，轴承的滚珠已经磨出肉眼可见的凹坑。更被动的场景是，传感器持续采集、持续上报，电池在不到一个维护周期内耗尽，维修人员到场时节点早已离线。

这类问题的根源在于沿用了几十年的固定采样模式——按固定间隔采集物理量，将模拟信号转换为数字信号，原封不动地转发给微控制器。整个过程没有数据理解，没有优先级判断，更没有决策能力。这种架构在数据量小、环境稳定的场合尚能运转，但放到工业振动监测、大规模环境感知、资产追踪中，缺陷立刻暴露：固定采样率要么漏掉瞬态冲击，要么在稳态下白白耗电；固定阈值无法区分真正的故障与正常的工况波动；上行链路被大量“一切正常”的冗余报文挤占。

推动感知层变革的两股力量均来自架构层面的下沉。

第一股力量是**边缘计算节点**部署到传感器集群附近——车间的工控机、楼宇中的智能网关、农业大棚内的采集箱。这些节点不需要云端的超强算力，但在本地完成滤波去噪、异常初筛和数据聚合绰绰有余。一种被广泛采用的分工原则是：云侧利用全量历史数据训练模型，边缘侧做低时延推理，端侧只执行最后一跳的快速响应【S2】。边缘节点承担了传统集中式处理中延迟最大的部分，将端到端响应时间从秒级压到毫秒级别。这种分工的工程收益在工业场景中尤为显著：一条产线上的振动传感器集群以毫秒级间隔采集，若全部裸数据都上传云平台，网络带宽和存储成本会急剧膨胀；边缘节点在本地完成特征提取后，上行数据量可显著减少。工程中需要注意的是，边缘节点的部署位置决定了其环境耐受要求：靠近车间的节点须具备工业级温度范围和防护等级；部署在户外杆塔的节点则须考虑雷击浪涌和宽温范围。

第二股力量是**端侧AI（TinyML）**与**自适应采样**的结合。端侧AI的核心思想是在毫瓦级功耗的微控制器上直接运行轻量级机器学习模型，让传感器节点摆脱对云端的依赖。这类模型经过量化压缩后，可以部署在主流32位微控制器上（如ARM Cortex-M系列）。部分厂商的工具链（如STM32Cube.AI）支持将训练好的模型转换为嵌入式代码，并提供运行时推理库【S5】。

自适应采样则瞄准通信环节：传统节点射频发送的能耗通常远高于本地计算。自适应采样的逻辑是让采样策略随环境状态动态变化。当读数长时间稳定在某个区间，采样间隔自动拉长，无线模块进入深度睡眠；当数据出现显著变化——温湿度骤升、振动能量陡增——采样频率自动提高，同时触发模数转换和射频发送，将关键事件推送到网关。直接收益是大幅延长电池寿命，间接收益是压减无效上行数据量，降低网络与云端存储成本。

然而，端侧AI与自适应采样并非适用所有场景。它们适合特征明确、模型规模可控的任务——振动异常分类、简单手势识别、设备故障初筛。对于需要融合多模态数据、理解长期活动语义的复杂任务，端侧算力依然不足。工程师在设计感知层方案时，需要做出的决策不再是“选一款传感器并接上”，而是系统性地判断计算负载如何拆分、推理任务放在哪一层、采样策略是固定还是自适应。

### 3.2.1 传感器工作原理与分类

一辆无人配送车从物流仓库出发，穿过自动门，驶上高速路。车里装着环境温度传感器、气压计、IMU惯性测量单元、激光雷达和摄像头——每一种器件都在用不同的物理原理截取外部世界的信息片段。温度靠热电效应，压力靠压阻效应，距离靠飞行时间。这些片段被整合成“路径可通行”“轮胎抓地力正常”“前方有施工障碍”这些判断，而后者的可靠性直接取决于前者的感知精度。

传感器是感知层的起点，也是整个物联网系统信任链条的根基。在物联网中，传感器节点由多个模块构成，模块功能包括感知、信息处理、收发网络信息、提供能量等【S6】。相比于传统传感器，物联网中的传感器具有协同、计算、通信等附加功能【S6】。

按被测物理量分类是工程中最常用的划分方式。温度、压力、光、声、磁、加速度、气体浓度——每种物理量背后对应着不同的换能机制。温度传感器最常见的是热电偶和热敏电阻：热电偶利用两种不同金属材料接合处的塞贝克效应，由温度差产生电动势；热敏电阻则依赖半导体的电阻率随温度剧烈变化。压力传感器大量采用压阻效应——硅微加工形成的薄膜在受压时发生形变，表面扩散的压敏电阻阻值随之改变。光学传感器里，光电二极管把入射光子转换为光电流。加速度计基于电容检测原理：微机械加工的可动电极与固定电极构成差动电容，惯性力改变电极间距，从而改变电容值。

关键性能指标是把传感器从一个元器件升格为工程选型依据的标准语言：

- **灵敏度**：输出变化量与输入变化量的比值。对加速度计，单位是mV/g；对温度传感器，常见单位是mV/°C或Ω/°C。同一芯片的输出量程固定时，灵敏度越高，可分辨的最小物理变化越小。

- **分辨率**：能检测到的最小输入变化。受噪声基底限制，分辨率不可能无限高。工程上需要区分理想分辨率与有效分辨率，后者以噪声均方根值对应的输入量来衡量。

- **线性度**：实际输出曲线在满量程范围内偏离理想直线的程度，通常用满量程百分比（%FS）或最大偏差值表示。线性度差的传感器需要分段校准，或者在数据处理环节做查表补偿。传感器厂家提供的拟合直线有端点法、最佳直线法等不同定义，选型时务必确认基线方法。

- **响应时间**：从被测物理量突然变化到传感器输出达到稳态值规定比例所需的时间。常见表达式是时间常数τ。响应时间必须匹配采样频率——用秒级传感器去监测毫秒级振动，结果只会是错失每一帧冲击。

这四个指标不是孤立的。灵敏度如果设得过高，在强信号时可能直接饱和；响应时间太短，噪声幅度会被放大，分辨率反而下降。选型需要反复权衡。

### 3.2.2 传感器接口与信号调理

传感器把物理量变成了电信号，但这往往只是漫漫长路的第一步——一个K型热电偶输出信号在微伏至毫伏量级，而微控制器的ADC通常期望输入范围在伏级。差值达四个数量级。不经过放大和滤波，读回来的数字量很难反映真实物理量。

从工程角度看，传感器与微控制器的接口分两大路径：**模拟接口**和**数字接口**。二者的分界线在于信号调理——放大、滤波、电平匹配——由谁完成。

**模拟接口**：MCU通过ADC把模拟电压翻译成数字量。这个看似简单的过程，拆开来是三个问题：

- **放大与电平匹配**：传感器输出幅度可能比ADC的参考电压小两个数量级。一条经验是，放大后的信号最大幅度应接近但不超过ADC的参考电压。以12位ADC、参考电压3.3伏为例，每LSB约0.8毫伏。热电偶输出直接接入，每LSB对应的温度变化可能超过实际可接受范围。解决方案是使用仪表放大器，把信号放大到接近参考电压。选型时需确认增益带宽积是否覆盖信号最高频率。

- **滤波**：工业现场最常见的是50赫兹（中国大陆电网频率）或60赫兹的工频干扰。对于温度这类慢变物理量，一个一阶RC低通滤波器足以把工频噪声压下去。工程上通常取截止频率为信号最高频率的3到5倍。例如室温变化最快每秒1摄氏度，信号最高频率视为1赫兹，截止频率取5赫兹。

- **采样率与量化位数**：ADC采样率应至少为信号最高频率分量的10倍。量化位数则取决于所需的最小可检测变化。

**数字接口**：传感器厂商把调理封装好了——内部集成了放大器、滤波器、温度补偿和线性化算法。MCU通过I²C、SPI或1-Wire总线读取数值，无需关心内部ADC的位数或放大器的增益。

两种接口的工程权衡：模拟接口开发周期长，但精度可控性高、单通道成本低；数字接口开发快，抗干扰能力强、总线可复用，但传感器单价较高。

信号调理的质量直接决定了传感器读数的可信度。理解模拟接口背后的每个环节，不是为了转向复杂——而是为了当数字接口无法满足精度或成本要求时，工程师能自信地自行搭建信号链。

### 3.2.3 传感器选型工程实践

选型不是翻手册挑参数最高的器件。数据手册上的“典型值”大多在实验室条件下测得，现场环境——温度波动、电源噪声、机械振动、电磁干扰——会把实际精度压下去。工程师的任务不是在最优参数里做加法，而是在项目约束下做取舍。

**选型核心维度**：

- **精度与分辨率**：先确定应用容许误差，再反推传感器精度要求，然后检查ADC位数是否足够。注意：精度、分辨率和线性度在数据手册上通常指理想参考条件下的数据。选型时要为真实环境预留余量。

- **成本与生命周期成本**：传感器单价只是表象。农业用的数字温湿度传感器单价可能很低，但工业温度探头在恶劣环境下稳定运行数年，前者可能几个月就漂移出规范。选型要把更换成本、维护人工、停工损失算进去。

- **功耗与供电方式**：电池供电的设备每微安都要精打细算；工业产线有稳定24V供电，对功耗敏感度低。选型时必须明确供电形式，并在系统层做功耗预算。

- **环境适应性**：防护等级、工作温度范围、抗腐蚀性、抗振动能力，这些指标在数据手册上往往被小字标注，但恰恰是现场失效的头号原因。

四个维度之间存在制约：高精度往往伴随高成本和高功耗；环境适应性更强的封装更大。没有“万能传感器”，只有“匹配场景的传感器”。

**假设场景：为智能温室选择温湿度传感器（示意案例）**

中型温室需监测温湿度，数据通过LoRa网关定期上报。供电方式为电池，要求续航至少一个生长周期。选型过程如下：

第一步：作物管理人员确认民用级传感器精度可满足需求。第二步：根据电池容量、上报频率和休眠电流做功耗预算。第三步：对比三款候选传感器——一款数字单总线接口，一款I2C接口带可配置报警，一款多合一传感器（含气压）。第四步：单总线协议对时序要求严格，长线传输易受干扰；I2C可用屏蔽线，可编程报警在MCU休眠时能独立触发；多一体化传感器功耗略高。最终选择I2C方案。第五步：出厂前做单点校准，现场用参考仪器做两点校准，同时修正偏移和增益。

### 3.3.1 RFID系统组成与工作原理

RFID（Radio Frequency Identification，射频识别）技术通过射频信号自动识别目标对象并获取相关数据，无需与被识别物体直接接触。无线传感网通过各个传感器节点相互协作来感知网络区域、采集处理监测信息，并传输给观测者【S6】。RFID系统由三部分组成——读写器、电子标签和天线【S12】。

- **读写器**：发送射频查询信号，接收标签返回的信号。在多标签环境下，读写器通过防碰撞协议区分同时响应的多个标签。

- **电子标签**：存储被识别物体的身份信息和其他数据。标签内部由天线和芯片组成，芯片中存储着电子产品代码（EPC）等数据。

- **天线**：在读写器和标签之间建立射频信号的传输通道。

标签类型按供电方式分为三种：

- **被动标签**：没有内置电池，依靠读写器发射的射频信号的能量来供电。工作距离通常较短（从几厘米到十米左右），成本最低，广泛应用于物流、零售领域。

- **半主动标签**：内置小容量电池为芯片供电，但通信仍然依赖读写器提供的射频能量。具有更高的读取灵敏度。

- **主动标签**：内置完整电源，可以主动发送射频信号，工作距离可达数十米甚至上百米。成本最高，但读取范围最远，适用于资产追踪和汽车收费等场景。

工作频率：RFID按工作频率分为低频（LF，125-134 kHz）、高频（HF，13.56 MHz）、超高频（UHF，860-960 MHz）和微波（2.45 GHz，5.8 GHz）四个频段。ISO 18000系列标准制定了各频段的空中接口协议。低频和高频RFID对金属和液体的适应性更好；超高频RFID的读取距离最远且数据传输速率最快，但易受金属和液体的干扰。工程实践中，金属表面需要使用抗金属标签，液体环境需调整天线极化方向。

### 3.3.2 RFID防碰撞与数据读取协议

当多个标签同时处于读写器的询问区域内并同时响应时，会发生标签碰撞（Tag Collision），导致读写器无法正确识别任何一个标签。这一现象需要引入防碰撞协议。

防碰撞算法主要有两种：

- **ALOHA算法**：基于时分多址（TDMA）的概念。标签在随机时间点发送数据，碰撞后随机延迟重发。标签数量较少时效率较高，密度增加时碰撞概率急剧上升。

- **二进制搜索算法**：读写器通过逐位询问的方式缩小搜索范围。算法将寻呼命令中的冲突比特位分离出来，只有序列号满足条件的标签回复，建立无冲突的通信环境。标签数量多且需逐个识别时更为高效。

EPC Gen2协议是目前应用最广泛的UHF RFID协议标准。它定义了读写器与标签之间的通信链路和标签存储结构。标签存储结构通常包含四个独立的内存区：TID区（标签制造商信息）、EPC区（电子产品代码）、User区（用户自定义数据）、预留区（安全信息）。读取速率受限于防碰撞算法效率和数据包传输速率，工程中需评估密集场景下的标签数量，预留通信时间余量。

### 3.3.3 RFID在物联网中的应用场景分析

自动识别技术是使物联网区别于其他网络的主要特点【S6】。RFID作为重要的自动识别技术，将物理世界与信息世界统一在一起。

**假设场景：RFID在智能仓储中的应用（示意案例）**

一家中型仓库需要管理数千种库存物品，出入库频率较高，现有的人工扫码方式效率低、易出错。在仓库出入口安装UHF RFID读写器形成读取覆盖区，所有入库物品贴被动式UHF标签。当叉车搬运托盘经过出入口时，读写器自动捕获标签的EPC码，无需停车扫描。

出入库效率从人工扫码提升到自动识别，盘点时间大幅缩短。工程需注意金属和液体对UHF信号的干扰，需要配合抗金属标签、调整天线极化方向等现场调试工作来克服。

### 3.4.1 定位技术概述：室外与室内

定位技术是采用某种计算方式，测量在指定坐标系中人、物体、事件发生的位置的一种技术，是物联网发展和应用的主要研究方向之一【S6】。

室外定位：全球导航卫星系统（GNSS）包括美国的GPS、中国的北斗、俄罗斯的GLONASS和欧盟的Galileo。在室外环境中，GNSS是首选的定位方式，成本低、覆盖广、实时性好。多星座接收机通过同时跟踪多个卫星系统，可提升定位可用性和收敛速度。

室内定位：室内环境无法接收GNSS信号，需要依赖其他无线技术：

- **Wi-Fi室内定位**：基于接收信号强度指示（RSSI）。成本较低，可利用已有的Wi-Fi基础设施，但精度受多径效应和环境变化影响较大。

- **蓝牙定位（BLE）**：利用蓝牙信标广播进行定位。成本低、部署灵活，典型精度在数米范围，适用于零售导览和人员定位。

- **UWB定位**：利用纳秒级脉冲信号实现高精度定位，抗多径干扰能力强，但成本较高。

**表3-2 室外与室内定位技术对比**

| 技术 | 精度 | 覆盖范围 | 功耗 | 成本 |
|-----|------|---------|------|------|
| GNSS | 室外米级 | 全球（室外） | 高 | 低 |
| Wi-Fi | 数米至十数米 | 50-100米 | 中 | 低（利用已有基础设施） |
| BLE | 数米 | 10-50米 | 低 | 低 |
| UWB | 分米级 | 10-50米 | 中 | 高 |

> 精度、功耗描述基于行业共识的定性表述，具体指标受环境、硬件配置和算法影响。

### 3.4.2 定位算法基础：三角测量与指纹法

定位算法的核心是解决“如何根据已知信号测量值来确定未知位置”的问题。两种主要的算法路径是三角测量法和指纹法。

三角测量（Triangulation）通过测量多个参考点与目标之间的几何关系来解算目标位置。根据测量方式的不同，又可细分为：

- **到达时间（ToA）**：通过测量信号从目标到多个基站的飞行时间来确定距离，需要时钟严格同步。UWB常采用此方法。

- **到达时间差（TDoA）**：通过测量信号到达两个基站的时间差，构造双曲线定位。不需要目标与基站间的精确时间同步。

- **到达角（AoA）**：通过测量目标信号到达基站的角度，结合基站位置进行定位。

- **RSSI测距**：基于信号传播衰减模型估算距离，精度不如ToA。

在三点定位基础上，工程上常用最小二乘法进行修正，以缓解测量噪声的影响。

指纹法（Fingerprinting）的基本思想是在定位区域内建立一个“信号特征指纹库”。方法分两个阶段：离线阶段在参考点上采集各基站的信号强度，记录为指纹向量；在线阶段移动目标采集当前位置信号特征，与指纹库匹配估算位置。指纹法对多径环境适应性较好，但指纹库的建立和维护需要周期性更新，增加了部署和维护成本。

### 3.4.3 多源融合定位工程实践

每种定位技术各有优劣。单独依赖一种技术往往难以满足所有场景的需求。例如，GPS在隧道内完全失效，Wi-Fi指纹在环境大变后需重建。

**假设场景：AGV在仓库中的多源融合定位（示意案例）**

在仓库内部署了多台自主导航AGV（自动导引运输车）。室内环境包含大量金属货架，对无线信号的干扰显著。AGV自主定位方案融合了惯性测量单元（IMU）读数和UWB定位数据。仅靠IMU会随时间积累误差（漂移）；仅靠UWB在金属货架密集区可能会间歇性丢包。IMU提供高帧率的相对位置更新；UWB提供低帧率的绝对位置修正，消除累积误差。

卡尔曼滤波是实现多源融合的常用方法。它是一种递归的状态估计算法，能够把具有不同噪声特性的测量信息融合起来，得到比单一测量更优的估计结果。

部署注意事项：UWB基站的安装位置需保证AGV在任何工作区域都能被至少三个基站覆盖；基站和AGV的时钟同步精度直接影响ToA测距精度；IMU的零偏需在上电初期进行静态校准。

### 3.5.1 边缘计算节点硬件与部署

算力的分布模式正在从传统的“集中式云计算”向“云-边-端”协同架构演进。边缘计算节点被部署到数据产生的源头附近，在本地完成部分数据处理、分析甚至决策，从而降低网络带宽需求、减少延迟并提升系统响应的及时性。边缘计算将为物联网赋能，提升物联网的性能，促使物联网在各个垂直行业落地生根【S11】。

边缘计算节点硬件选型的核心是处理器架构。ARM Cortex-A系列适合运行通用的Linux系统和应用程序，处理能力较强，常见于工业平板、轻量级网关。ARM Cortex-M系列功耗低，可运行实时操作系统（RTOS）。x86架构在算力要求较高时选用，成本也更高。

**表3-3 常见边缘计算节点硬件对比**

| 平台 | CPU架构 | 内存（典型） | 功耗（典型） | AI能力 |
|------|--------|------------|-------------|--------|
| Raspberry Pi 4B | ARM Cortex-A72 | 2-8 GB | 约5-10W | 有限：CPU推理 |
| Jetson Nano | ARM Cortex-A57 + GPU | 4 GB | 约5-10W | 支持GPU/CUDA推理 |
| STM32MP1 | ARM Cortex-A7 + M4 | 512 MB-1 GB | 约2-5W | 有限：MCU级推理 |

部署位置的选择需要权衡现场条件（如供电、温湿度、防护等级）、物理安全和维护便利性。户外杆塔、矿井等恶劣环境需要更高防护等级和宽温范围。

### 3.5.2 边缘节点上的数据预处理与过滤

边缘计算节点的最大价值不是替代云端，而是分担云端处理的压力。数据产生在边缘，但核心训练和复杂建模通常在云端进行。边缘节点负责的是过滤和聚合——把无数传感器产生的海量裸数据压缩成特征更突出、信息密度更高的元数据后，再上传云端。

数据预处理任务：

- **滤波去噪**：对于连续变化的物理量（如温度、压力、振动），边缘节点可在本地执行滑动平均滤波、中值滤波等算法，去除尖峰噪声，保留有效趋势。

- **异常检测**：基于简单的阈值规则或统计方法，在本地对数据进行异常标记或告警。边缘节点可以直接触发本地动作（如下发停止指令、关闭设备），反应速度更快。

- **数据聚合与格式化**：将一段连续时间窗口内的原始数据打包成一个统计摘要（如最大值、最小值、平均值、标准差），上传少量具有代表性的数据。这能大幅降低网络带宽和云端存储负担。

滑动窗口大小需要根据物理量的变化速率进行调节。窗口太小时，滤波效果不明显；窗口太大时，可能掩盖短时脉冲异常。对于温度这类慢变信号，一个10点到100点的窗口通常足够用。

### 3.6.1 端侧AI：TinyML概述与部署工具

智能传感器是用嵌入式技术将传感器与微处理器集成为一体，使其成为具有环境感知、数据处理、智能控制与数据通信功能的智能数据终端设备【S5】。端侧AI（TinyML）正是智能传感器从概念走向工程实现的最主要技术路径。

TinyML是指在功耗和计算资源都极为有限的嵌入式设备（如微控制器）上，部署和运行机器学习模型的技术和方法的统称。其核心思想是把模型从云端下载到设备本地，直接在数据产生的地方进行推理，从而避免因持续上传所有裸数据带来的高能耗和高带宽占用。TinyML通过模型量化、剪枝、知识蒸馏等压缩技术，将模型大小缩减到KB级别，并优化成能在MCU上运行的整数运算。

部署流程与工具链：TinyML模型的部署大体分为三步：

1. **模型训练**：在云端或PC上使用TensorFlow、PyTorch等框架训练模型。
2. **模型转换与量化**：使用TensorFlow Lite Micro、STM32Cube.AI等工具，将浮点模型转换为适合嵌入式设备的格式。
3. **嵌入式部署**：将转换后的模型固件烧录到Cortex-M系列MCU或其他嵌入式硬件上，通过C语言API加载并运行。

TensorFlow Lite Micro是Google推出的轻量级推理引擎，支持在微控制器上运行，已被用于关键词识别、动作分类、异常检测等任务。STM32Cube.AI是STMicroelectronics推出的AI工具链，可一键将训练好的神经网络模型转换为优化的C代码。

模型量化是TinyML部署的最关键步骤之一。将32位浮点权重和激活值转换为8位整数精度，在不显著降低模型准确率的前提下，可使模型大小压缩为四分之一，推理速度提升数倍。

### 3.6.2 自适应采样：动态调整数据采集频率

在典型的传感器节点能耗构成中，射频发送占据主导地位，本地计算的功耗远低于射频通信。自适应采样的核心思路是：仅在需要的时候（数据发生显著变化或事件被触发时）才唤醒节点采集数据并发送，其余时间让射频模块进入深度睡眠模式。

基于事件驱动的采样：传感器节点只在检测到“事件”发生时（如加速度超过阈值、温度突升）才唤醒整个系统完成数据采集和发送。需要为每个传感器设定一个可信的“事件阈值”。

预测模型触发采样：如果节点上部署了TinyML模型，且模型可以在本地预测未来几秒的数据趋势，即可基于“预测结果是否可能超出安全边界”来决定后续采样和通信行为。

采样策略类型：
- **变化率策略**：当数值的变化速率超过预设阈值时，采样间隔缩短。
- **时间窗口策略**：设置一个基本采样间隔，只要数值变化在“死区”范围内，仍按原间隔采样，但上报前进行过滤。
- **混合策略**：结合事件触发和基本轮询，既保障对突发事件的捕获，又确保节点不会因完全依赖事件触发而丢失长时间的慢漂移。

**假设场景：振动传感器自适应采样节省电池（示意案例）**

一家工厂在大型旋转设备上部署电池供电的振动监测节点。默认情况下，节点以较高采样率采集振动加速度数据。边缘节点本地监测加速度的峰值是否超过预设的稳态阈值。稳态阶段仅在振动水平接近阈值时触发高频采集窗口，峰值未超阈则进入深度睡眠。检测到超限冲击后，记录数据包并上报云平台，同时将阈值下调以对后续冲击更加敏感。

工程注意点：变化率阈值和基本采样间隔需根据数据特性调优。阈值设得太宽会导致事件丢失；设得太窄则节点频繁唤醒。节点硬件需考虑深度睡眠模式下的状态维护（如维持实时时钟）。

### 3.7.1 物模型 Profile概念与必要性

在现实物联网项目中，设备接入是一个典型的多对多问题：不同厂商、不同型号、不同接口协议的设备，产生的数据格式、量纲、通信方式千差万别。若数据格式无法统一，平台侧需为每个设备开发专用的“数据适配器”，显著增加系统集成成本。物模型，也称 Thing Model / Profile正是为了解决这种异构设备互操作难题的一把钥匙。

物模型可以被理解为“一类设备的能力模板”——它把同型号设备共有的属性（位号）、指令（服务）、事件聚合在一起，描述这类设备的“数字身份”。一个具体的物理设备通常属于一个物模型；当多个同型号设备被集成进系统时，它们可以复用同一个物模型，从而避免重复建模【S4】。

主流物模型标准：
- **W3C Web of Things (WoT) Thing Description (TD)**：W3C标准，将设备的能力用JSON-LD和I/O数据模式表达。
- **OneM2M**：以资源、属性和属性值为基础模型进行统一建模。
- **IoT DC3 Profile**：开源物联网平台IoT DC3中使用的物模型概念，以“位号、指令、事件”三个核心子模型构成，描述了设备“能采什么、能控什么、会报什么”【S4】。

物模型三大核心要素（WoT TD标准）：
- **Properties（属性）**：设备的状态变量（如当前温度、湿度值），通常对应来自感知层的位号值流。
- **Actions（服务/指令）**：设备可被执行的操作（如执行校准、设置目标温度）。
- **Events（事件）**：设备主动通知外部（如温度越界告警、故障发生）。

为什么要统一物模型：
1. **平台对接**：统一的物模型是平台无关应用程序开发的基础。
2. **设备影子**：通过物模型可标准化存储设备属性状态。
3. **从感知层到应用层的统一**：物模型创造了一种统一的数据描述语言，数据在每一层的传递只需解释属性含义，而无需解读原始报文的字节级含义。

### 3.7.2 物模型设计示例：温度传感器

为了更好地理解如何在实践中定义物模型，此处采用W3C Web of Things的Thing Description (TD)规范，为一个简化版的温度传感器编写JSON格式的物模型。

**假设场景：某厂商温度传感器物模型定义（示意案例）**

该传感器为工业级数字温度传感器，具备基本测温输出、校准功能和温度越界报警事件。

**物模型定义的JSON示例（基于WoT TD规范，示意）**：

### 3.7.3 物模型在数据互通中的实践

物模型的引入不仅整合了感知层设备，它更深远的影响在于打通了“感知层到应用层”的统一数据模型。实践中的一个典型考验是：当边缘网关采集不同厂商的传感器数据时，如何在上行到云端平台前统一数据格式。

设备影子是一个上层概念：云平台为每个设备在云端维护一个“虚拟映射”，记录设备的理想属性状态和最后上报的真实属性状态。设备影子与物模型结合——物模型定义了属性的合法性（数据范围、单位），而平台根据物模型校验。

一个成熟的物联网平台，允许应用开发者在“设备+物模型”的基础上构建业务逻辑，而非关心设备是哪个厂商的。例如，智慧园区中统一使用物模型“智慧灯杆”，平台开发告警规则时只关注属性，而不会因为设备协议不同而写两套规则。

在IoT DC3平台中，物模型被定义为“一类设备的能力模板”【S4】。物模型管理接口提供了API供外部系统创建和查询物模型【S3】。在这种架构下，数据从感知层节点上行的比特流，最终统一为带有语义的位号值（Point），而每个位号的量程、精度、单位都由对应的物模型定义。

### 3.8 工程检查清单

本章沿着“从设备物理原理 → 选型部署 → 边缘处理 → 智能化升级 → 设备抽象”这条逻辑线展开。以下检查清单旨在指导开发者在设计感知层方案时，系统地避免常见工程陷阱。

**表3-4 感知层技术工程检查清单**

| 检查类别 | 检查项 | 说明/行动点 |
|---------|--------|------------|
| **传感器选型** | 精度余量是否足够？ | 数据手册指标在实验室测得，现场至少留2倍裕量。 |
| | 接口与MCU匹配？ | 模拟接口需要放大器、滤波和采样率匹配；数字接口需确认I²C/SPI时序兼容。 |
| | 功耗预算是否精确？ | 将休眠、唤醒、射频发射电流全部累加，计算连续工作时间。 |
| | 环境适应性 | 在实际温度、湿度、腐蚀、振动环境中，最差情况能否正常工作？ |
| **RFID选型与部署** | 工作频段与介质 | UHF在金属/液体环境表现差；需考虑抗金属标签或调整极化方向。 |
| | 标签密度与读取效率 | 计算单标签读取周期，预留通信时间余量。 |
| **定位方案选型** | 精度是否满足？ | 根据场景需求选择UWB还是BLE等，成本预算与精度匹配。 |
| | 定位算法（三角/指纹） | 指纹法依赖环境指纹库，环境改变后需重建。 |
| **边缘节点** | 部署环境 | 防护等级、温度范围、供电稳定性是否满足现场需求？ |
| **端侧AI** | 推理时效 | 模型编译后，MCU实际推理时间需满足响应时间要求。 |
| **物模型** | 属性/事件定义是否完整？ | 关键报警事件、服务定义要完整，数据格式必须明确。 |
| **整体方案** | 工作量评估 | 评估感知层（含现场部署）的工时，比纯软件研发多留出余量。 |
